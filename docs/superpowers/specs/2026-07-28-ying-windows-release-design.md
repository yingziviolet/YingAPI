# Ying Windows 1.0 交付设计

日期：2026-07-28  
状态：已确认

## 目标

在不更换现有技术栈的前提下，把当前 Ying 项目交付为其他 Windows 用户可以下载、安装并使用的桌面应用。

最终产物：

- `Ying-portable.zip`：免安装版，解压后运行 `Ying.exe`
- `Ying-Setup-1.0.0.exe`：Windows 安装包
- 两个产物对应的 SHA-256 校验值
- GitHub `v1.0.0` Release，包含上述下载文件和简要使用说明

## 不在本轮范围

- Tauri/Rust 迁移
- 自动发布流水线
- 商业代码签名
- macOS/Linux 打包
- 质量回评、pgvector 索引和渠道权重路由
- 重新设计现有控制台

## 架构

保留现有 React + FastAPI + pywebview + PyInstaller + Inno Setup：

1. `Ying.exe` 在 `%LOCALAPPDATA%\Ying` 准备数据库、管理令牌、加密密钥和日志。
2. 启动器选择可用的本地端口，在后台线程启动仅监听 `127.0.0.1` 的 FastAPI 网关。
3. 健康检查成功后，pywebview 在主线程创建独立 Ying 窗口并加载 React 控制台。
4. 关闭原生窗口时退出整个进程，后台网关随之停止。
5. WebView2 缺失或原生窗口启动失败时，显示可操作的错误提示并允许用系统浏览器打开；此时托盘菜单负责重新打开控制台和退出网关。

不修改现有网关数据面和控制面业务逻辑。

## 启动与数据流

### 首次启动

1. 取得单实例锁；已有实例时提示“Ying 已在运行”并退出。
2. 创建 `%LOCALAPPDATA%\Ying`。
3. 生成本机管理令牌和 Fernet 密钥。
4. 创建 SQLite 数据库并选择可用端口。
5. 启动 FastAPI，等待健康检查。
6. 打开原生窗口。
7. 控制台发现尚无渠道或虚拟 Key，进入“一步配置”页面。
8. 用户配置成功后进入仪表盘。

### 后续启动

沿用已有数据库、令牌和密钥，直接进入仪表盘。旧版本 `%LOCALAPPDATA%\LLMGateway` 数据继续兼容，不自动搬迁或删除。

### 卸载与升级

程序文件安装到 Windows 应用目录；用户数据始终留在 `%LOCALAPPDATA%`。升级覆盖程序文件，卸载不删除数据库、密钥和日志。

## 错误处理

- 数据目录或密钥创建失败：显示错误和目标路径后退出，避免无提示失败。
- 端口不可用：在有限范围内顺延；仍失败则显示错误并退出。
- FastAPI 健康检查超时：显示 `gateway.log` 路径并退出。
- WebView2 缺失：提示安装运行时或改用浏览器。
- pywebview 抛出异常：写入日志并进入浏览器/托盘回退。
- 重复启动：第二个进程显示提示并退出，不同时访问 SQLite。

## 安全

- HTTP 服务只绑定 `127.0.0.1`。
- 发布物和 Git 仓库不包含真实 API Key、管理令牌、数据库或 Fernet 密钥。
- 首次配置仍在本地生成虚拟 Key，真实上游 Key 加密落库。
- GitHub 发布前检查工作树和待上传文件，避免把 `.env`、数据库或本地日志加入提交。

## 界面
